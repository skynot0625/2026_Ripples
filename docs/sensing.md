# 센서와 공간 기억

## 입력 자료

`data_led_example/sensors`에는 실제 혈 ZIP과 비콘/맥 규격이 있다. ZIP 내부 프로그램을
실행하지 않고 `sample/stream.bin`만 읽는다. 실제 혈 기록은 ToF 479장, 천장 패킷 2,783개,
약 59.23초이며 위쪽 센서는 ID 0 하나다. 비콘 위치는 현재 합성이다.

ToF 메시지는 `[u32 header length][u32 payload length][JSON header][payload]`.
깊이와 confidence가 각각 240×180 u16 little-endian으로 이어진다. 회전 보정 후
confidence≥60, 0<depth≤4m만 사용한다. 3×3 영역의 유효 깊이 중앙값과 유효 화소 비율을
저장한다. 낮은 신뢰도의 고정 채움값은 실제 거리로 쓰지 않는다.
위쪽 포인트는 valid/status/거리 범위를 검사한다.

맥은 44,100Hz/16bit/3채널 비압축 PCM WAV + metadata.json이다. SHA256·frames를 확인하고
장치/세션/start_frame 순서로 처리한다. 중복은 건너뛰고 누락/겹침은 오류로 알린다.
세 마이크의 파형을 먼저 더하지 않고 대역 에너지를 계산한 뒤 평균한다.
저음 <400Hz, 중음 400~2,000Hz, 고음 ≥2,000Hz. 선형 에너지를 평균하며 dBFS는 표시 변환에만 사용한다.

## XY와 표상

가상 방은 10×10m, 네 모서리 비콘, 기준 RSSI -59dBm@1m, 지수 4.
`P_mW=10^(RSSI/10)`, `d=10^((RSSI_1m-RSSI)/(10*4))`로 거리 추정 후 강건 최소제곱 XY를 구한다.
반경 3.2m 원을 60초에 돌고 맥은 반대 위상이다. 좌표/보정값은 실측 설치값이 아니다.

두 기구의 XY는 탑 수평면에 대응한다. 혈 카메라는 작은 3×3 청록색 기둥,
위쪽 포인트는 중심의 보라색 끝점. 거리 z는 `0.12+0.70*clip(d/4,0,1)`.
카메라 유효 화소 비율이 밝기에 반영된다. 맥 저/중/고는 높이 18/46/74%,
호박/산호/자홍색이며 대역 에너지를 -60~-6dBFS 범위에서 밝기로 바꾼다.

표상의 높이는 특징 축이며 실제 벽/천장 높이나 음원의 위치 복원이 아니다.
센서 자세/설치 높이가 없는 상황에서 공간 구조를 실측 3D로 단정하지 않는다.

## 평균·표준편차

같은 위치 셀의 같은 특징을 1초 단위로 평균한 뒤 n, mean, M2를 누적한다.
std=`sqrt(M2/(n-1))`, n<2이면 추정하지 않는다. 이는 1초 특징 평균들의 편차이며
PCM 자체의 표준편차나 평균의 표준오차가 아니다. 결측은 0으로 채우지 않는다.

Activate는 동일 표상을 찍고 `exp(-dt/0.9)`로 감쇠한다. 약 2.7초에 5%로 줄고
아주 작은 잔여값은 0이 된다. 두 기구의 현재 흔적은 계속 갱신되지만 통계는 보존한다.
Sleep은 이동 궤적을 재생하지 않고 위치별 평균장을 그린다. mean±std의 표상 차이에
공간적으로 부드러운 잡음을 곱해 아른거림을 만든다. 시간상수 1.8초, 기본 강도 0.45.
std=0이면 효과가 없고, 평균/뉴런 동역학은 바꾸지 않는다. 관측 횟수를 밝기에 곱하지 않는다.

## 비교 데모

`python -m ripples.demo`는 합성 3채널 음성을 240초 생성한다. 위치별로 음색을 다르게 하고
재방문 시 세기를 달리해 실제 합성 샘플의 통계에서 std를 얻는다. metadata의 demo=true와
SYNTHETIC-MAEK 장치명으로 구분한다. 원본/기존 DB와 분리된 `runtime/dream-demo`를 사용한다.
Sleep은 네 바퀴의 학습된 평균/std, Activate는 첫 바퀴다. 미래를 예측하는 실시간 비교가 아니다.

동일 스파이크와 동일 노이즈 시드를 사용해 `activity`와 `slow_waves`를 비교한다.
방사형 효과는 실제 burst가 트리거지만 렌더러가 만든 모양이다. 모델의 자연적인
공간 전파라고 해석하지 않는다. 주기적 사인파를 신경망에 추가하지 않는다.

## 파일 감시와 남은 연결

`--watch`는 완성된 기록 파일을 10초마다 확인한다. 동일하게 커지는 stream.bin을 반복
가져오는 방식이 아니다. WAV+metadata를 완성한 후 디렉터리를 입력 폴더에 옮기는 방식을 권장한다.
이미 가져온 파일을 입력에서 치워도 저장된 통계는 남는다. 입력 원본의 장기 용량은 별도 관리한다.

실시간 입력은 [센터 브리지와 원시 TCP](realtime.md)를 사용한다. 파일 재생과 달리
실측 RSSI만 사용하고, 위치가 없으면 센서 특징을 공간 기억에 누적하지 않는다.
실측 비콘 좌표/기준 RSSI와 공간 범위를 설정한 뒤 demo DB와 분리된 measured DB를 쓴다.
현재 M30의 확정 좌표 5개는 `live.m30.json`에 반영했다. 사용자가 선택한 RF 미보정
상대 RSSI 모드는 대략적인 XY이며 추후 누적을 명시적으로 켤 때 **estimated DB**에 따로 쓴다. calibrated=false는
좌표 미확정이 아니라 RF 미보정을 뜻한다. 두 모드 모두 fresh 노드 3개 미만은 누적하지 않는다.
설정 fingerprint가 다른 DB에 새 값을 섞지 않는다. 방향/외부 자세 보정은 아직 없으므로
카메라 3×3 배열은 기구 중심의 센서 축이고, 세계 좌표상의 물체 점군은 아니다.

센터 `/api/maek`의 `mics`는 정규화 음량 3개다. 새 `mic_level_0..2` 특징으로 저장하고
높이 10%의 밝은 베이지 3점으로 표현한다. 주파수나 PCM 전력으로 환산하지 않는다.
PCM 입력은 기존 `band_low/mid/high` 규칙을 그대로 쓴다. 두 경우 모두 Activate/Sleep의
표상 규칙은 같으며, Sleep은 해당 특징의 평균·표준편차를 사용한다.
현재 앱은 WAV 원본을 저장하고 `stored:true`를 회신하는 업로드 서버가 아니다.

현재 운영은 `ripples.receive` 수신 점검만이며 데이터 누적은 OFF다. `ripples.live`도
`--accumulate` 없이는 DB를 열지 않는다. 기본 예시/실행 스크립트의 추가 방사형 파동은 OFF다.
`ripples.demo --read-only`는 기존 합성 데모 통계를 읽어 추가 파동 없는 2화면 예시를 만든다.
옛 3화면 비교가 필요할 때만 `--compare-waves`를 명시한다.
